## Bugs found and fixed during the run

1. **`McpEvaluationResult` shape mismatch** — `evaluateContract` consumer
   indexed `result.failed_done_criteria.length`, but the backend returns
   `failed: string[]` / `passed: string[]` / `warnings: string[]` /
   `status: string` / `run_id: string`. Crashed 3.7 with
   `Cannot read properties of undefined (reading 'length')`.
   Fix: realigned `McpEvaluationResult` in
   [src/mcp/types.ts](../src/mcp/types.ts) and the toast formatter in
   [src/commands/ledger.ts](../src/commands/ledger.ts).

2. **Newly created evidence invisible to claim picker** — `recordClaim`
   read evidence from `packet.claims.flatMap(c => c.evidence)`, but the
   backend's `/cases/{id}/packet` only includes evidence already bound to
   a claim. Brand-new evidence was never visible, so 3.6 hit
   `Record at least one Evidence before binding a Claim` even after a
   successful 3.5. Fix: added a session-local `pendingEvidence` cache to
   [src/store/ledgerStore.ts](../src/store/ledgerStore.ts)
   (`rememberEvidence` / `getAllEvidence`), and made
   [src/commands/ledger.ts](../src/commands/ledger.ts)'s `recordEvidence`
   write into it. The cache invalidates itself once `refreshPacket` reports
   the evidence as bound.

3. **Approve Gate filter rejected `pending` status** — Both
   [src/polling.ts](../src/polling.ts) (status bar count) and
   [src/commands/approveAction.ts](../src/commands/approveAction.ts)
   (Approve Gate QuickPick + webview's Approve button) only accepted
   `pending_decision`. LocalProof's `suggest-actions` produces
   `pending`, so freshly suggested actions were invisible to the UI and
   the Approve & Execute button rendered disabled. Fix: widened the
   filter in both call sites and in
   [media/approveGate.js](../media/approveGate.js)'s button-disabled
   check to accept `pending` || `pending_decision`.

## Next-iteration items

These are not blockers for shipping v0.2 to a `.vsix`, but they're worth
filing once the screenshots anchor is closed:

- **Better multi-step InputBox flow.** When a contract has 4–5 sequential
  prompts, a single ESC silently aborts the whole chain. Either
  consolidate into a webview form, or surface the prompt index ("3 of 5
  — Forbidden actions") so the user knows whether they finished.
- **Pre-finish snapshot guard.** `finishWorkLedger` should run a final
  snapshot (or at least warn) before POSTing to `/finish`, instead of
  letting the backend 400 on a missing snapshot.
- **Backend-side 400 surfacing.** The 400 from finish was rendered as a
  generic error toast and immediately followed by the success toast,
  which is confusing. The progress task should either swallow the
  success toast on error, or render both as a single combined message.
- **GIF deferred.** `docs/assets/proofflow-v0_1_x-vscode-flow.gif` and
  `docs/assets/proofflow-v0_1_x-dogfood-vscode.gif` (Demo_Asset, task
  7.2) are still outstanding under the same backlog anchor.
