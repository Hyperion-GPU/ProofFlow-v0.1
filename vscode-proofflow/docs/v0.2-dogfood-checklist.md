# VSCode v0.2 Dogfood Checklist

This doc captures the end-to-end manual run that exercises every M1–M4 surface
and produces the two screenshots `PLANS.md` lists under
`vscode-channel-screenshots-deferred-from-v0-1-x-dogfood`. It is intentionally
runnable from a fresh terminal — paths use `<TMP>`/`<REPO>` placeholders so the
captures stay free of personal directories.

> All commands assume PowerShell on Windows. Adjust quoting for bash if needed.

## 0. Prereqs

- ProofFlow repo cloned at `<REPO>` (this branch).
- Python 3.11+ available.
- VS Code 1.85+.
- Notifications, terminal title, and other personal context blanked out before
  recording (see the privacy block at the bottom).

## 1. Bring up the backend

In one terminal:

```powershell
cd <REPO>\backend
python -m uvicorn proofflow.main:app --port 8787
```

Wait for `Uvicorn running on http://127.0.0.1:8787`. Quick sanity check from
another shell:

```powershell
curl http://127.0.0.1:8787/health
```

Should return `{"status":"ok",...}`.

## 2. Launch the extension

```powershell
cd <REPO>\vscode-proofflow
npm install
npm run build
```

In VS Code, open `<REPO>\vscode-proofflow` as a folder, press `F5` to launch
the Extension Development Host. In the new dev-host window, `File → Open
Folder...` and pick `<REPO>` (or any test workspace) so ledger `repo_path` and
relative source refs resolve cleanly.

Expected status bar progression:

1. Briefly `Backend offline` while the first poll is in flight
2. `🛡 ProofFlow` once `/health` succeeds (within ~1s)
3. `🛡 ProofFlow (N)` later, where `N` is the count of pending actions

## 3. Exercise the Work Ledger lifecycle

Run from the command palette (`Ctrl+Shift+P`):

| Step | Command | Notes |
|------|---------|-------|
| 3.1  | `ProofFlow: Ledger — Start Work Contract` | Objective: `Dogfood v0.2 ledger UI`. Allowed scope: `vscode-proofflow/`. Forbidden actions: `force push to main`. Done criteria: `tests pass`. |
| 3.2  | `ProofFlow: Ledger — Record Algorithm Decision` | Pick the case from step 3.1. Approach: `Direct REST client`. Rationale: `Backend already exposes typed JSON; MCP server returns agent-text`. Alternatives: `MCP stdio (deferred — see CHANGELOG 0.2 notes)`. |
| 3.3  | `ProofFlow: Ledger — Record Cost Budget` | Limits: `≤ 30 min runtime`. Expected ops: `manual dogfood`. |
| 3.4  | `ProofFlow: Ledger — Capture Snapshot` | Phase: `start`. Repo path: workspace root. |
| 3.5  | `ProofFlow: Ledger — Record Evidence` | Type: `note`. Content: `Approve Gate webview captured`. Source ref: `vscode-proofflow/src/webviews/approveGate.ts:1-30`. |
| 3.6  | `ProofFlow: Ledger — Record Claim` | Pick the evidence from 3.5. Severity: `medium`. Text: `Approve Gate webview surfaces medium/high claims`. |
| 3.7  | `ProofFlow: Ledger — Evaluate Contract` | Read the toast — captures pass/fail headline. |
| 3.8  | `ProofFlow: Ledger — Finish` | Final summary: `Dogfood complete`. |

After 3.6, click the case in **Active Ledger** → the Case Detail webview
opens. Sit on the **Evidence & Claims** tab. **This is screenshot #1.**

## 4. Approve Gate flow

From the ProofFlow sidebar context menu, run **Scan with ProofFlow** on a
small folder under the workspace. The backend will emit a `move_file` /
`mkdir_dir` action with `pending_decision`.

Status bar should now show `🛡 ProofFlow (1)`. Run
`ProofFlow: Approve Gate & Execute`, pick the action — the rich Approve Gate
webview opens. **This is screenshot #2.**

Confirm:

- Left pane shows `From / To / Reason` rows.
- Right pane lists every medium/high claim with an `Explain` button.
- `Open inline view` button is present and resolves to a real source line
  when clicked.
- `Approve & Execute` runs the action and the panel closes.

## 5. Export Proof Packet

Back in the Case Detail webview header, click `Export Packet`. Verify:

- A file at `<TMP>\.proofflow\exports\<case-prefix>-<timestamp>.md` is
  created.
- A markdown preview tab opens automatically.
- Toast says `Packet saved to .proofflow/exports/...`.

## 7. Privacy scrub

Before saving any capture:

- Close every other private repository in the workbench.
- Replace any visible personal path with `<TMP>` (terminal prompt, status
  bar, breadcrumb). If paths leak, **reshoot — do not blur**.
- Blank Windows notification center.
- Token placeholders only: `.mcp.json` / `.codex/config.toml` should show
  `<MCP_TOKEN>`.
- Run `Select-String '[A-Z]:\\Users\\' -CaseSensitive:$false` on any
  exported markdown packet — must return 0 hits.

## 9. What to log if anything fails

Open `Output → ProofFlow` and copy the last block of log lines. Common
failures:

- `Backend offline` persists — uvicorn isn't running, or the port is busy.
  Check the uvicorn terminal first.
- `proofflow.backendUrl` mismatch — the dev-host workspace may have a stale
  `.vscode/settings.json`; clear it or point it at `http://127.0.0.1:8787`.
- A ledger command throws `404` — the case was finished or evaluated; refresh
  the Active Ledger view and pick a still-open case.

When in doubt, run `ProofFlow: Show Logs` and paste the relevant excerpt
into the dogfood report.
